# 아이스하키 1대1 PvP — 설계 문서 (첫 공개 MVP)

작성 2026-11-06. 근거: 사용자와의 대화, 조작감 시험판(`hockey-spike/`), 사용자의 기존 서비스 게임 pop-battle 코드 열람.
표기: **[결정]** = 사용자가 정한 것, **[제안]** = 작성자(Claude)가 정한 것(사용자 확인 전), **[미정]** = 아직 정해지지 않은 것.

## 1. 의도와 이유

- 골프 캐디 RPG는 재미가 없어 폐기했다. 에셋과 파이프라인은 살린다. **[결정]**
- 새 게임은 **3D 아이스하키 팀 경기**이며, 최종 형태는 **FC 온라인 같은 구조**다. **[결정]**
  - PC: 내가 팀을 직접 조작해 1대1 온라인 대전.
  - 모바일: 직접 조작하지 않는다. 선수단 관리, 전술, 감독 모드(AI 경기 관전 + 교체·작전) 중심. 모바일 조작은 불편하다는 판단. **[결정]**
- 이유: 북미에서 스포츠 장르 인기가 높고, 아이스하키는 북미 정체성이 강하다. 기존 하키 게임(모바일 Hockey Stars, Smash Hockey 등)은 대부분 단순한 1대1 샷 대결이라, **3D 팀 하키 + 웹 즉시 플레이**는 빈자리로 판단. 시장 규모는 데이터로 확인하지 못했다.
- 사용자는 Verse8에서 멀티게임(pop-battle)을 성공적으로 서비스 중이며, 같은 플랫폼에 올린다. **[결정]**
- 조작감 시험판(3대3 vs AI, 자동 선수 전환·패스·힘 모아 슛·몸싸움)을 직접 해 본 사용자 평가: **재밌다.**

## 2. 이번 마일스톤: 첫 공개

- **기한:** 다음 주 중 Verse8 공개. **[결정]**
- **성공 기준:** 1대1 PvP가 지연 없이 된다. **[결정]**
  - "지연 없음"의 측정 기준 **[제안]**:
    - 내가 조작하는 선수의 반응: 입력 후 다음 프레임에 움직임(로컬 예측). 체감 입력 지연 50ms 미만.
    - 상대 선수·퍽 표시: 실제보다 150ms 이내 뒤처짐, 순간이동·되감김이 눈에 띄지 않음(왕복 지연 150ms 이하 환경 기준).
    - 퍽 소유 전환(패스 받기·빼앗기)이 양쪽 화면에서 같은 결과로 보임.
    - 3분 경기를 끊김 없이 끝까지, 양쪽 점수가 같음.

### 2.1 첫 공개에 들어가는 것 **[제안]**
1. 1대1 온라인 경기: 각자 3명 스케이터 + 골리(AI)로 구성된 팀을 조작. 60초 × 3피리어드(피리어드마다 진영 교대), 동점이면 60초 골든골 연장, 그래도 동점이면 슛아웃.
2. 매칭: 빠른 대전(무작위 1명 매칭) + 친구와 방 만들기(방 코드). pop-battle의 로비/방 구조를 참고.
3. AI 연습전(시험판 수준의 3대3 vs AI): 혼자 들어와도 할 것이 있도록. 매칭 대기 중에도 가능하면 좋음.
4. 기본 캐릭터 2~3종(그림체 혼합 확인용, 능력치 동일), 팀 색 구분.
5. PC 조작(키보드, 게임패드는 가능하면). 모바일에서 열었을 때는 "PC에서 플레이" 안내 또는 관전·AI 연습 정도. 모바일 감독 모드는 이번에 넣지 않음.
6. 결과 화면(점수, 슛·세이브 수), 간단한 전적(승/패) 저장.

### 2.2 이번에 넣지 않는 것 (다음 단계)
- 강화 시스템, 재화, 상점, 선수 수집.
- 랭크 래더·시즌.
- 모바일 감독 모드·선수단 관리.
- 실제 NHL 팀/선수 (라이선스 필요, 가상 캐릭터로 간다).

## 3. 게임 규칙 (시험판 기준, 첫 공개용) **[제안]**
- 링크: NHL 규격 근사(61×26m, 코너 반경 8m), 보드 반사, 골대 그물·포스트 충돌.
- 팀: 스케이터 3 + 골리 1. 골리는 항상 AI.
- 조작(PC): FC 온라인 키 배치를 따른다. **[결정]** 방향키 이동, E 질주, S 짧은 패스 / 퍽 없을 때 선수 전환, W 스루 패스(받는 선수 앞 빈 공간), A 띄우는 패스(공중이라 스틱으로 못 끊음), D 꾹 눌러 힘 모아 슛 / 놓으면 발사 / 퍽 없을 때 몸싸움. 별도 선수 전환 키·카메라 전환 키 없음(카메라는 옆 중계 고정). 퍽 가진 선수로 자동 전환, 퍽을 뺏기면 퍽에 가장 가까운 선수로 자동 전환. (시험판 반영 완료)
- 슛: 힘을 모을수록 빠르지만 덜 정확. 골리는 반응 지연이 있어 잘 노린 강슛은 막지 못함.
- 오프사이드·아이싱·페널티 없음(아케이드).
- 시험판 AI끼리 기준: 3분 경기당 평균 3.3골, 슛 성공률 16%. 공격권 전환이 너무 잦음(경기당 40~60회) → 줄이는 조정 필요.
- 카메라: 가로 화면, 옆 중계 시점 기본, 골대 뒤 시점 전환.

## 4. 기술

### 4.1 정해진 것
- 플랫폼: Verse8, 서버는 Agent8 GameServer(`$global`/`$room` 상태, 원격 함수, 룸 메시지, `$roomTick`). **[결정]**
- 클라이언트: 웹(three.js). pop-battle은 TypeScript strict + Vite + three.js + Rapier. **[제안: 같은 스택]**

### 4.2 Agent8에서 확인한 제약 (pop-battle 코드 기준)
- 서버 주기 처리 `$roomTick`은 200ms(5Hz). pop-battle은 단계 전환·시간 종료에만 사용.
- pop-battle 이동 동기화: 각 클라이언트가 자기 상태를 20Hz로 보내고, 받는 쪽은 스냅샷 보간. 서버는 명중·점수 등 결과만 검사.
- 따라서 **서버가 퍽 물리를 계산하는 구조는 불가능**(5Hz). 룸 메시지 왕복 지연은 아직 측정하지 않았다.

### 4.3 동기화 방식 **[제안, 첫 작업에서 검증]**
- **호스트 권위 + 게스트 예측:** 한 클라이언트(호스트)가 경기 전체(퍽·선수 8명·골리)를 고정 120Hz로 계산하고 20~30Hz로 스냅샷을 보낸다. 게스트는 입력을 30Hz로 보내고, 자기가 조작하는 선수만 로컬 예측 후 호스트 값으로 부드럽게 보정, 나머지는 보간 표시.
- 대안(호스트 방식의 게스트 체감이 기준을 못 맞출 때): 퍽을 가진 쪽이 퍽을 계산하는 소유권 방식.
- 첫 작업은 **넷코드 시험판**: Agent8 룸 메시지로 왕복 지연·전송 빈도 측정, 호스트/게스트 체감 확인. 결과에 따라 방식 확정.
- 결과 검증: 첫 공개에서는 양쪽 클라이언트가 보고한 점수가 일치할 때만 전적 기록(불일치 시 무효). 강화·랭크가 들어가기 전에 더 강한 검증 방식 필요.

### 4.4 캐릭터·그림체 **[결정: 혼합]**
- 골프 데모의 미형 여성(Swordsman, Casual Girl 8, Mixamo 뼈대)과 pop-battle 같은 비현실·장난감형을 모두 쓴다.
- 판정은 체형과 무관하게 동일(몸통 반경, 스틱 길이). 차이는 능력치로만(다음 단계).
- 팀 구분: 유니폼 일부 팀 색(pop-battle의 팀 컬러 마스크 방식), 발밑 링, 이름표.
- 스케이팅 모션 필요(사람형은 Mixamo에서, 장난감·마스코트형은 캐릭터별 애니메이션 세트). 골프 데모의 캐릭터별 애니메이션 세트 구조(`reactions.js` ANIM_SETS 방식)를 재사용.
- 모바일 성능: Swordsman급은 무거움 → 6명 동시 표시용 경량화(골프 데모의 텍스처 축소·진단 도구 재사용).
- 쓸 수 있는 보유 에셋: Mixamo 모션, Quaternius Ultimate Animated Character(CC0, 치비 52종), 골프 데모 GLB 2종. Unity Asset Store 보유분에 하키 전용은 없음. Unity 에셋의 웹 사용 허용 여부는 미확인.

## 5. 다음 단계 (첫 공개 이후, 방향만)
- **강화:** FC 온라인처럼 성공/실패가 있는 두근거리는 강화. 높은 단계일수록 확률 하락, 실패 시 하락 가능, 보호 수단. **[결정: 두근거리는 방식]**
- **능력치 vs 실력:** 능력치는 중요하지만 절대적이지 않음. 실력이 받쳐야 이김. **[결정]** → 최대 강화와 기본의 차이를 속도·슛 파워 기준 대략 10~15% 이내로 제한. **[제안]**
- **선수 수집:** 작게(시간·에셋 한계). 핵심은 강화와 경쟁. **[결정]**
- **경쟁:** 시즌제 1대1 랭크, 랭크 점수 기반 매칭. **[제안]**
- **모바일:** 선수단·강화·전술 관리, 감독 모드. **[결정: 방향]**
- 북미 유저의 "돈 쓴 팀이 이긴다" 반감 → 위 능력치 상한과 매칭으로 대응. **[제안]**

## 6. 하지 않을 것 / 실패로 볼 것
- 강화가 실력을 압도하는 구조.
- 실제 리그·선수 라이선스 없이 실명 사용.
- 모바일에서 직접 조작 경기를 핵심으로 만드는 것.
- 첫 공개에서 지연이 체감되는 온라인 경기(성공 기준 미달이면 공개 연기 또는 AI 연습전만 공개를 검토).
